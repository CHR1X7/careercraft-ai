Project Overview: AI-Powered Job Application Assistant
Welcome to your first AI project!
This assignment challenges you to build an AI-Powered Job Application Assistant.
Vision: To build a tool that fundamentally streamlines the job application process, giving users back their
time and providing them with an AI-powered co-pilot to land their dream job. Please see if you can make
this browser extension or web-application rather than a desktop solution.
Core Features (The "What"):
1. Autofill Agent: Securely stores a user's profile information (name, contact info, work history,
education, etc.) and intelligently fills out application forms across different websites.
2. Resume-to-JD Scoring Agent: Analyzes a user's uploaded resume against a specific job
description (JD), provides a "match score," and generates actionable insights on how to tailor their
resume to better fit the role.
3. Tailored Answer Agent: Analyzes the job description and the user's profile to generate
high-quality, personalized answers to common application questions like, "Why are you a good fit
for this role?" or "What is your biggest strength?".
4. Dashboard : The ability for a single screen to be able to walk the user(s) through where their
application has been. Potential values: Not Submitted yet, Submitted, Received initial Response,
Interview Requested, Rejected after Interview, Onsite/Video Interview Requested, etc.. (feel free
to come up with this as you see fit)
Various Role Involvement: Each role (Data Scientist, Frontend Engineer, Backend Engineer) has
distinct responsibilities. See the tabs on the left side for role specific assignments.
● Frontend Engineers (The User's Champion): You are in charge of the entire user experience.
Your goal is to create an intuitive, trustworthy, and even delightful interface for our users to interact
with the AI agents. You will bring the "magic" to life.
● Backend Engineers (The Engine & Infrastructure): You should try to build the robust and
scalable systems that power the entire application. You'll create the APIs, manage data, and
ensure the AI agents can be deployed, monitored, and maintained effectively. You are the
architects of the system.
● Data Scientists (The Intelligence): You will design and build the core intelligence of the
product—the AI agents themselves. You will work on scraping data, structuring prompts for Large
Language Models (LLMs), and processing the results to deliver valuable insights to the user.
Key Concepts to Understand:
● AI Agent: Think of an agent not just as an AI model, but as a system that can perceive its
environment, reason about a goal, and take actions to achieve it. In our case, an agent's goal
might be "analyze this resume against this job description," and its actions would be to use tools
like a web scraper and an LLM.
● LLM (Large Language Model): This is the "brain" of your agent (e.g., GPT-4, Gemini). It's a
powerful reasoning and text-generation engine. We don't train the model itself; we learn how to
communicate with it effectively.
● Prompt Engineering: This is the skill of crafting precise instructions (prompts) to get the desired
output from an LLM. A well-designed prompt is the difference between a useless response and a
highly effective one. This is a responsibility for everyone, not just the data scientists.
● Tool Use: This is a core agentic design pattern. An agent doesn't do everything by itself. It uses
"tools"—which are just functions you write—to interact with the outside world. For this project, your
key tools will be:
○ A web scraper to get data from a job posting URL.
○ A database function to retrieve a user's profile.
● Structured Output (JSON): For an application to work reliably, the LLM can't just return random
text. We must force it to respond in a predictable format like JSON. This is done through prompt
engineering and is the critical "contract" between the data science logic and the backend server.
● API (Application Programming Interface): This is the set of rules and endpoints that the
backend provides so the frontend can communicate with it. It's the connective tissue of the entire
project. For example, the frontend will make an API call to POST /api/resume/analyze to
trigger the analysis agent.
● Agentic UX (User Experience for AI): Designing for AI is different from traditional UX. Key
principles include:
○ Showing the work: Let the user know the agent is working on their behalf.
○ Allowing intervention: Users must be able to edit or reject the AI's suggestions. The AI is
a co-pilot, not the pilot.
○ Collecting feedback: Incorporating simple feedback mechanisms is essential for knowing
if the agent is actually helpful.

Frontend Assignment
Frontend Engineer Assignment
As a Frontend Engineer, your goal is to be the user's champion. You will design and build the user
experience for the AI Job Assistant, creating an intuitive, trustworthy, and effective interface for
interacting with the AI agents. You will bring the "magic" of the AI to life for the user.
Phase 1: Pre-Office Hours Preparation (1 Week)
The goal of this phase is to move from idea to a design plan. You need to understand the unique
challenges of designing for AI and translate that understanding into a visual and interactive blueprint for
the application.
Actions:
1. Research Agentic UX: Review these resources and synthesize their key principles. How should
an application behave when an AI is performing tasks on the user's behalf?
○ Required Reading: Microsoft's UX Design for Agents
○ Required Reading: Secrets of Agentic UX
2. Map the User Journey: Create user flow diagrams to visualize how a user will interact with each
core feature. Think step-by-step:
○ Onboarding: How does a user securely create a profile and input their work history, skills,
etc.?
○ Activation: How does the user trigger the Autofill, Resume Score, or Tailored Answer agents?
Is it a browser sidebar? A pop-up?
○ Interaction & Feedback: How is AI-generated content (like resume suggestions or tailored
answers) presented? How does the user approve, edit, or reject it? Crucially, how will you
design a system for users to give feedback on the AI's quality (e.g., thumbs up/down)? This
feedback loop is essential for improving the product.
3. Create Low-Fidelity Wireframes: Using a tool like Figma, Balsamiq, or even just pen and paper,
sketch out the primary UI components.
○ Profile/Settings Screen: Where the user's data lives.
○ Main Assistant Interface: The primary view when the assistant is active on a job page.
○ Resume Score Modal/View: The dashboard showing the match score and improvement tips.
1
○ Generated Answer Component: The UI for showing suggested text and allowing the user to
copy or edit it.

the backend

Backend Assignment
Backend Engineer Assignment
As a Backend Engineer, you will build the engine of the AI Job Assistant. You will design and construct a
secure, scalable, and observable system that powers the entire application. You are the architect of the
infrastructure that enables the frontend and data science components to work together seamlessly.
Phase 1: Preparation
The goal of this phase is to design a robust backend architecture. You will define the technologies, data
flows, and infrastructure needed to support the application's features now and in the future.
Actions:
1. Research Agentic System Design: To build a system that supports AI agents, you need to
understand their unique requirements.
○ Required Reading: The Agentic AI Handbook
○ Required Reading: 4 AI Agent Strategies
2. Design the System Architecture: Create a high-level architecture diagram using a tool like
Lucidchart, draw.io, or even just boxes and arrows. Your diagram should show:
○ The Client: The Frontend application.
○ API Layer: Your Node.js/Express or Python/Flask application. Will you use an API
Gateway?
○ Core Logic: Where will the "agent" logic (developed by the Data Science team) plug in?
Will it be a separate service or integrated directly?
○ Database: Choose a database (e.g., PostgreSQL for structured data, MongoDB for
flexibility).
○ External Services: Show the connection to a third-party LLM API (e.g., OpenAI, Gemini).
3. Plan for Production Operations (optional): Think beyond just writing code. How will this run in
the real world?
○ Deployment Strategy: Focus initially to have this running locally.
■ Future think through: How will you package the application (e.g., Docker container)?
Where do you plan to deploy it (e.g., AWS, Vercel, Heroku)?
○ Logging & Observability: What tools will you use for logging API requests, errors, and
agent activity? How will you monitor system health (e.g., a /status health check
endpoint)?

🏆Phase 2: Development
Can start development even if not attend Office hours. Start focusing on building the foundation. Your
focus is on creating the API endpoints, setting up the database.
Actions:
1. Set Up Project & Database: Write a script to connect to your chosen database.
2. Define Database Schemas: Based on the Data Science team's data models, create the schemas
or models for your database
3. Build API Endpoints: Create the core API endpoints. Initially, these can return mock data, but
they should respect the data contracts you've agreed upon with the frontend team.
○ POST /api/users (Create a new user profile)
○ GET /api/users/{userId} (Fetch a user profile)
○ POST /api/resume/analyze (The main endpoint for the resume scorer)
○ POST /api/generate/answer (The endpoint for the tailored answer agent)
4. Integrate Logging: Add logging to your API endpoints from day one. Log incoming requests,
important processing steps, and especially any errors. This will be invaluable for debugging.
Remember to start simple, and build up complexity iteratively. Good luck!
